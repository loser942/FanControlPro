# FanControl Pro Win11 界面、Unicode 与告警稳定性设计

## 背景与目标

当前 Win32 版本已能在目标电脑上完成只读 EC 探测，但主界面和托盘通知将 UTF-8 中文字节传给多字节 MFC/Win32 API，导致中文及 `°C` 显示乱码。旧资源模板也采用大面积分组框，信息密度低，不适合 Windows 11 的日常使用。温度告警只使用单个布尔标志，温度在阈值附近来回波动时会重复弹出通知。

本次改动将同时解决显示、布局和告警三个问题，并保留已完成的启动安全规则：程序启动后仅只读探测，必须由用户明确勾选接管控制后才可能写入风扇寄存器。

## 范围

包含：

- 将应用 UI、资源与托盘通知迁移到 Unicode 宽字符路径，所有用户可见文字使用中文。
- 将主窗口改为紧凑双栏布局：左侧监控，右侧控制，默认折叠高级设置，底部固定配置操作。
- 为温度通知增加可测试的状态机、5 C 回差和 10 分钟最短通知间隔。
- 在高级设置中加入桌面通知开关、告警温度和最短通知间隔；未启用桌面通知时仍保留主界面告警状态。
- 保持 Win32 构建和现有 x86 `ClevoEcInfo.dll` 的运行方式。

不包含：

- 修改 EC 地址、风扇控制曲线算法或增加新的硬件型号支持。
- 将应用重写为 WinUI、WPF 或更换 MFC。
- 更改现有配置文件格式以外的数据迁移工具。

## 设计决策

### 1. Unicode 与 EC 兼容边界

工程的 `CharacterSet` 改为 Unicode。MFC UI 层使用 `CStringW`、宽字符串字面量和 `SetWindowTextW` 等 Unicode API；格式化后的 UI 文本通过 `swprintf_s` 或 `CStringW::Format` 生成。资源文件继续使用 UTF-8 代码页，所有资源文本为中文。

`ClevoEcInfo.dll` 的加载、导出函数查找、旧配置文件路径和诊断日志仍保留显式 ANSI 边界，例如 `LoadLibraryA`、`GetProcAddress`、窄字符路径缓冲区。这些边界只接收 ASCII DLL 名称或由 UTF-16 安全转换出的系统路径，不能让 Unicode UI 字符串隐式流入 DLL 接口。

验收条件：主窗口、模式下拉项、实时温度、按钮、启动状态和托盘通知均正确显示中文和 `°C`；EC DLL 的加载和只读初始化日志仍成功。

### 2. Windows 11 紧凑双栏主窗口

资源模板调整为固定的紧凑内容区域，并允许用户通过窗口边框放大。窗口使用 `Segoe UI`，统一 9-10pt 字号、8-12 DLU 间距和清晰的标签层级，不添加自绘主题或不稳定的非标准控件。

左栏为“运行状态”：CPU/GPU 温度、大号温度文本、进度条、RPM、使用率与一行启动/告警状态。右栏为“风扇控制”：控制模式、接管控制、强冷、两路风扇滑块与数值编辑框。接管未授权或核心未就绪时，所有可能写入风扇的控件保持禁用，状态文字说明原因。

高级设置默认隐藏。点击“高级设置”后在主窗口下方展开，包括更新间隔、过渡温度、强冷温度、线性模式、GPU 锁频、预设、最大转速和告警设置；再次点击折叠，窗口恢复紧凑尺寸。窗口缩放时使用最小尺寸和 `WM_SIZE` 布局规则维护两栏宽度，避免控件重叠或文字截断。底部始终固定“加载配置”“保存配置”“重置默认”。

验收条件：1024x768 与常见高 DPI 桌面下可完整使用；默认状态中主要监控和手动控制在首屏可见；高级项不占用默认空间；文本不重叠、不截断。

### 3. 温度告警状态机与节流

新增独立、无 MFC 依赖的告警决策组件。输入为 CPU 温度、GPU 温度、告警阈值、通知启用状态、当前时间和上次通知时间；输出为当前是否告警、是否允许发送桌面通知。

- 任一温度首次达到或超过阈值时进入告警状态。
- 只在进入告警状态时尝试通知；若距离上次通知不足配置的最短间隔（默认 10 分钟），则仅更新界面状态。
- 两路温度均低于 `阈值 - 5 C` 后才重新布防，防止阈值附近波动重复弹窗。
- 关闭桌面通知时不调用 Shell 通知，但主界面状态仍显示“温度告警”。
- 托盘通知使用 `NOTIFYICONDATAW` 和 `Shell_NotifyIconW`，标题为“FanControl Pro 温度告警”，内容包含 CPU/GPU 当前温度。

默认告警阈值维持当前值 90 C；高级设置允许设置 60-100 C 的阈值和 1-60 分钟的通知间隔，默认启用桌面通知。配置加载失败或值越界时使用安全默认值并写入诊断日志。

验收条件：温度高于阈值时最多发送一次；在温度未同时降至回差线以下前不重复告警；回差恢复后下一次越阈值可告警；通知文字正常显示中文。

## 数据流与错误处理

后台核心周期性更新温度，调用告警决策组件。组件决定是否通知，核心负责把告警状态投递给 UI，并且仅在允许时调用 Unicode 托盘通知。界面从核心读取状态并刷新文本；高级设置的输入经范围校验后写入核心配置。

任何 DLL 初始化失败、配置读取失败或通知 API 失败都不能弹出后台模态消息框，也不能改变风扇接管授权状态。失败以中文状态文本和诊断日志呈现。通知 API 失败仅记录日志，温度监控与界面告警继续运行。

## 测试与验证

- 为告警决策组件编写独立 C++17 状态测试，覆盖首次越阈值、回差、冷却时间、关闭通知和 CPU/GPU 任一路温度触发。
- 扩展启动状态测试：在 `UiReady`、`CoreStarting`、`CoreFailed`、`Exiting` 中，即使用户授权也不得写入风扇；退出中不得允许接管。
- Win32 Debug 与 Release 构建必须通过。
- 在 `D:\Download\Fans` 使用真实 EXE 启动，确认进程可响应、日志中 DLL 加载与只读初始化成功、中文 UI 和通知无乱码。部署前保留现有 EXE 备份，测试过程中不勾选接管控制。

## 风险与回滚

Unicode 迁移的主要风险是旧 ANSI 文件和 DLL 接口被隐式改变。实现将对这些接口使用显式 A 版本调用和局部转换，不作全局字符串替换。部署时将旧可执行文件备份为时间戳文件；若真实启动验证失败，可立即恢复该备份。
