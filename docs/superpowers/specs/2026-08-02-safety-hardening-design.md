# FanControl Pro 安全性加固设计

## 目标

消除已验证的风扇接管误判、传感器失效、EC 控制权争夺、配置损坏、自启失效和 Unicode 路径问题。程序在不确定硬件状态时必须停止自行写入 EC，并恢复 BIOS 控制。

## 全局约束

- 保持 Win32、Visual Studio 2022 v143、静态 MFC 和 Windows 10 SDK 构建目标。
- 未获得用户明确授权时，任何普通控制、强冷或温度紧急路径均不得写入 EC。
- 不更改 Clevo EC 寄存器映射、DLL 导出函数签名或风扇曲线算法。
- 保持对现有 v3 `FanControlPro.cfg` 的读取兼容；迁移后写入新格式。
- 所有新增状态机与持久化逻辑必须有不依赖 MFC 或硬件 DLL 的 C++ 诊断测试。

## 接管验证与 EC 回退

控制状态从单一的“调用过 DLL 写函数”改为可测试的会话状态机。每次目标占空比发生变化或开始接管时，状态机进入 `Requesting`：记录两个风扇的目标值、写入发生时间和连续匹配计数。只有在写入后的有效时间窗口内，两路 EC 回读连续两次都在现有 15 个百分点阈值内时，才进入 `Active`。

任一回读偏差会使连续匹配计数归零。相同时间窗口内的三次重新夺回用尽预算后，状态机进入 `Fault`，核心线程只执行一次 `SetFanDutyAuto` 归还 BIOS，然后停止后续风扇写入。UI 显示“接管状态异常”，保留复选框状态供用户主动取消或重新发起接管；它不得继续显示“接管已生效”。

DLL 的 `SetFanDuty` 没有返回值，因此“已调用写入函数”只能被记录为“写入已发出”，不能被称为“写入成功”。实际生效只由上述连续 EC 回读确认。

## 传感器与线程生命周期

温度采样异常重试改为等待 `m_hExitEvent` 的可中断等待。连续三轮采样异常后，传感器状态进入 `Fault`，核心线程停止普通曲线、强冷和刷新写入，并调用同一线程中的 `ResetFan()`。UI 的控制状态继而显示故障，旧温度只可用于最后一次诊断显示，不能继续驱动风扇占空比。

`Run()` 是唯一执行硬件复位的路径：退出事件、传感器故障和接管验证失败都在核心线程内复位。`Uninit()` 与析构函数只释放 DLL 和普通资源，避免在 UI 或析构线程中与控制循环并发写 EC。

初始化失败保留当前行为：不进入控制循环、设置 `CoreFailed` 并投递失败通知。此次不为它引入新的结果枚举，因为当前审查未证明线程继续控制或覆盖 UI 状态。

## 配置持久化与并发

配置文件使用显式磁盘结构，而不再序列化 `CConfig` 的内存前缀。`ConfigV4Disk` 包含 v3 已持久化的所有标量和数组字段，不包含 `ConfigPath`、对象布局或填充字节。读取器接受 v3 旧文件，将其归一化后转换为 v4 内存配置；新保存一律输出 v4。

保存流程为：在 `CCore` 配置锁内复制配置快照，锁外写入 `<cfg>.tmp`，刷新文件缓冲区，将现有文件替换为 `<cfg>.bak`，再以 `MoveFileExW` 的写穿透替换正式文件。正式文件无效或截断时，读取器尝试 `.bak`，两者都失败时才加载默认值。UI 不再直接对解锁后的 `m_config` 调用 `SaveConfig()`；通过 `CCore` 的快照保存接口完成。

## 自启、命令执行与 Unicode 路径

自启操作拆分为查询、创建和删除三种明确函数。取消勾选必须调用删除路径，不再将查询误用为删除。注册表查询读取完整命令行，并与当前 EXE 的带引号路径比较；任务计划查询以进程退出码为准。

任务计划命令使用宽字符 `CreateProcessW`，不捕获 stdout/stderr，因此不存在管道满载等待；操作结果根据退出码判断，不能依赖“成功”或“拒绝访问”等本地化文本。该同步操作仅在用户点击自启控件时发生。

模块路径、EC DLL、GPU DLL、任务 XML 和任务命令均使用宽字符路径。`GetProcAddress` 仍传递 ASCII 导出名称，保持 DLL ABI 不变。

## 强冷授权策略

维持保守策略：未授权时不写 EC。强冷复选框和托盘菜单在未授权时必须回退为关闭状态，并通过启动状态区域说明“请先启用风扇接管”；不得只改变界面状态。温度紧急路径遵守同一授权门槛，只显示告警，不能隐式接管。

## 测试与验收

- 控制验证测试覆盖两次连续回读成功、目标变更后重新验证、超时、偏差和抢回预算耗尽。
- 传感器健康测试覆盖瞬时异常、连续三次异常进入故障和故障后禁止写入。
- 配置测试覆盖 v3 读取迁移、v4 保存读取、主文件损坏时从备份恢复和未完成临时文件不影响读取。
- 授权测试覆盖未授权强冷不进入可写状态。
- 现有启动、温度通知和对话框布局测试继续通过。
- Win32 Debug 与 Release 生成均成功；在真实设备上只做未授权只读启动验证，人工确认中文路径下 DLL 仍能加载以及故障状态不会写入 EC。
