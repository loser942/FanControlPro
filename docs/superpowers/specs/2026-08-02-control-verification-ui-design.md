# FanControl Pro 控制生效确认界面设计

## 目标

让用户在默认主界面中能清楚分辨“程序正在监控”与“程序已经实际接管并向 EC 写入风扇占空比”，并消除温度已经恢复后仍显示告警的错误状态。高级设置默认折叠，避免截图中出现的大面积参数区干扰日常确认。

## 默认界面

默认窗口保持两栏和底部配置操作。左栏显示 CPU/GPU 温度、RPM 与使用率；右栏显示模式、接管复选框和两路目标占空比。高级设置默认折叠，按钮文字为“高级设置”；只有用户点击后才展开完整参数区。

监控栏新增固定的“控制状态”区域，按以下状态显示中文文本和颜色：

- 灰色“BIOS 控制中”：核心未就绪、未勾选接管，或用户已取消接管。
- 蓝色“正在请求接管”：已勾选接管但尚未收到一次成功 EC 写入与回读。
- 绿色“接管已生效”：至少一次写入成功，且最新 EC 实测占空比与目标占空比的偏差不超过现有 15 个百分点阈值。文本同时显示 `CPU 目标 xx% / EC xx%` 和 `GPU 目标 xx% / EC xx%`。
- 红色“接管状态异常”：已授权但连续回读偏差超过阈值，或者核心初始化失败。此状态不自动持续写入以外的额外命令，保留现有重新夺回机制和诊断日志。

“验证接管”不新增会改变曲线的按钮。状态只使用原有控制循环中的实际 `SetFanDuty` 写入记录和下一次 EC 回读，因此不会额外制造风扇转速突变。

## 状态数据与线程边界

`CCore` 新增一个 UI 可读取的控制状态快照：用户是否授权、是否已成功写入、最近一次写入的 CPU/GPU 占空比、最近一次 EC 回读的 CPU/GPU 占空比、回读是否在阈值内，以及核心启动状态。生产者只在核心线程的写入/读取路径更新；UI 线程只读取原子快照，不能直接读取非原子 `m_bTakeOverStatus`。

每次 `SetFanDuty` 成功调用 DLL 后记录实际写入的 EC 值；每次 `Update` 获得 EC 数据后记录回读占空比，并按 15 个百分点阈值计算是否一致。状态文本必须把“已授权”与“已生效”分开，禁止仅依据复选框判断接管成功。

## 告警显示

启动状态与温度告警使用两个独立的静态文本控件。温度告警为真时显示红色“温度告警：请检查散热状态”；告警解除时显示绿色“温度正常”。它不再覆盖核心初始化状态。温度告警的判断继续使用现有 90 C 默认阈值、5 C 回差与 10 分钟通知冷却规则。

## 错误处理与安全

控制状态异常、EC 初始化失败和配置读取失败只更新 UI 与诊断日志，不弹出后台模态框，也不改变用户的接管授权。程序启动时仍保持 BIOS 控制；只有 `CoreReady && userAuthorized` 可写风扇。EC DLL 保持 x86 ANSI 接口，不改地址、导出名称或风扇曲线。

## 测试与验证

- 为控制状态判定创建不依赖 MFC/EC DLL 的 C++17 测试，覆盖未授权、已授权未写入、写入后回读一致、回读偏差过大、核心失败和取消接管。
- 现有启动安全、温度告警回差测试必须继续通过。
- Win32 Debug 和 Release 均须构建通过。
- 在 `D:\Download\Fans` 启动 Release 版本，确认核心日志中 EC DLL 加载和只读探测成功；未勾选接管时状态为 BIOS 控制，用户勾选接管后状态仅在实际写入与回读一致时转为“接管已生效”。测试前保留现有 EXE 备份。
